# 항공 여행 일정 플래너 — 기획 결정서 (2일차 기준)

> **이후 변경 (3일차)** — 이 문서는 2일차 기획 기준입니다. 바뀐 점:
> - 인천 시설(면세점 등) API 가 있습니다: 인천국제공항공사 상업시설 정보(StatusOfFacility). '공항 시설' 화면과 `get_incheon_facilities` 도구로 씁니다.
> - 인천 운항은 승인된 '여객기 운항 현황 상세 조회'(StatusOfPassengerFlightsDeOdp)를 씁니다. 응답의 items 가 목록으로 바로 오는 형식입니다.
> - 한국공항공사 편명 상세는 실시간 info(탑승구 포함)를 씁니다.
> - 최신 설계는 [AGENT.md](AGENT.md), [TOOLS.md](TOOLS.md), [API.md](API.md), [SPEC_CHECK.md](SPEC_CHECK.md) 를 보세요.

Agent 기반 도메인 플래너 서비스(프로젝트 명세서 3회차)의 도메인을 **항공 여행 일정 플래너**로 확정하고, 어떤 API를 어떻게 쓸지 정리한 문서입니다.
이 문서의 결정을 바탕으로 `api_check/check_apis.py`(API 연결 확인)를 먼저 실행하고, 결과에 따라 Tool 구현으로 넘어갑니다.

## 3. 대표 요청과 제약 (명세 2.2)

요청에서 뽑을 조건은 세 가지로 나눕니다.

- **기준 조건**: 날짜, 시각 (예: "내일 오전")
- **선호 조건**: 출발 공항, 목적지, 항공사, 국내/국제 구분
- **제약 조건**: 공항 도착 기한, 체크인 여유 시간 (사용자 입력)

| 번호 | 사용자 요청 예 | 필요한 Tool | 재계획 여부 |
|---|---|---|---|
| S1 | "내일 오전 9시 이후 인천에서 출발하는 일본행 편, 체크인 여유 2시간 확보 가능한 걸로" | 운항 목록(ICN) → 상세 | 후보 0건이면 날짜 +1일 → 시간창 확대 (최대 3회) |
| S2 | "토요일 김포에서 제주 가는 편, 오후 6시 전에 출발하는 것" | 운항 목록(GMP, 목적지 CJU) → 상세 → 혼잡도(GMP) | 후보 0건이면 재계획 |
| S3 | "지금 인천 출국장 혼잡해? 오전 10시쯤 가도 괜찮을까?" | 승객 예고(인천) | 재계획 없음 (사실 조회) |
| S4 | "이 편 도착지 지도 보여줘" | 상세 → 지도 링크 생성 (Tool 아님, 실행 흐름이 직접 처리) | 없음 |
| S5 | "같은 날 다른 시간으로 바꿔줘" | 직전 조건 기억 → 시간 조건만 갱신 → 운항 목록 재조회 | 없음 |
| S6 | "사용법 알려줘" | Tool 없음 (계획 단계 건너뜀) | 없음 |
| S7 | "김포에서 다음 주 목요일 편" (D+6 초과) | 운항 목록 (날짜를 가장 가까운 허용일로 조정하고 응답에 밝힘) | 없음 |
| S8 | "출발 시각 정보가 없는 편만 있을 때" | 상세 → 판단 불가로 제외 | 없음 |

재계획 조건 정리
- 재계획은 **제약을 충족하는 후보가 하나도 없을 때만** 합니다.
- 키 누락, 인증 실패처럼 다시 시도해도 결과가 같은 경우에는 재계획하지 않고 바로 안내합니다.
- 재계획 상한은 **3회**. 도달하면 멈추고 사유와 함께 조건을 조정할 수 있는지 되묻습니다.
- 재계획 시 이미 받은 Tool 결과는 다시 호출하지 않습니다.

## 4. 사용 API 5종과 채택 결정

| # | API (명세 파일) | 제공 | 주요 항목 | 역할 | 제약 · 주의 |
|---|---|---|---|---|---|
| A | 인천 항공기 운항 현황 상세 조회 (`9a06022b`, IIAC `statusOfAllFltDeOdp`) | 인천 출·도착 편 (조회일 기준 −3일 ~ +6일) | 편명, 항공사, 상대 공항, 예정·변경 시각, 터미널, 탑승구, 체크인 카운터, 상태 | **핵심 (공통)** | 1분 갱신. 요청 목록 중 `searchdtCode` 기본값은 변경시간(E) |
| B | 실시간 항공기 운항정보 조회 (`c18d05d7`, KAC `flight-status`) | KAC 14개 공항의 출·도착 편 (D−3 ~ D+6) | 편명, 항공사, 상대 공항, 예정·변경 시각, 상태, 국내/국제 구분 | **핵심 (공통)** | 응답에 게이트·터미널 없음. 상세 목록에는 편명 필터가 없음 |
| C | 공항 혼잡도 (`1bc76eae`, KAC `airport-congestion`) | 김포·제주·김해·청주·대구 **5개 공항만** | 구간별(체크인→신분확인→보안→탑승) 혼잡도 1~4 레벨 | 보조 (KAC 5개 공항) | 5개 공항 외에는 데이터 없음. 갱신 주기 명세에 없음 |
| D | 인천 출입국별 승객 예고 (`e9d4b805`, IIAC `passgrAnncmt`) | 인천 T1·T2 입국장·출국장 시간대별 인원 (오늘·내일) | T1 출국장 1~6번, T2 출국장 1~2번, 합계 | 보조 (인천 전용) | 5분 갱신. 1터미널 6번 출국장은 교통약자 출구라 예상 혼잡도에서 제외됨 |
| E | 공항 상업시설 임대계약 (`cb2aff9a`, KAC `airport-retail-contract`) | KAC 공항의 상업시설 (업체명, 층, 국내/국제선) | 계약 시작·종료일, 층 수 | 보조 (KAC 공항) | 공항 코드 없이 지사명만 있어 매핑표 필요. 종료일이 지난 계약이 포함됨 (샘플: 2019년 종료) |

연결 방식
- 필수 Tool 세 종(명세 F3002~F3004)을 **외부 API 툴 다섯 개**로 나누어 구현합니다 (7장 참고).
- Google Maps는 "목적지를 지도로 보기" 기능이라 모델 판단이 필요 없으므로 **Tool이 아니라 실행 흐름이 직접 처리**합니다 (명세 2.3).

### 4-1. 개발계정 호출 한도 (공공데이터포털 검색 결과 기준, 신청 화면에서 재확인)
- KAC 운항 스케줄, KAC 혼잡도, KAC 상업시설: 개발 5,000건/일
- 인천 승객 예고: 개발 1,000건/일 (운영 신청 시 1,000,000건/일)
- 인천 운항현황(A): 검색 결과에서 한도를 확인하지 못함

→ 같은 요청을 반복하지 않도록 **결과 캐시(예: 5분)**를 둡니다. 특히 승객 예고는 하루 1,000건이라 캐시가 필수입니다.

### 4-2. 승객 예고 대민 서비스 주의
공공데이터포털 안내에 따르면 승객 예고를 "예상 혼잡도" 성격의 대민 서비스에 쓰려면 **사용자 안내 문구를 제공기관 관리부서와 협의**해야 합니다. 화면에는 "예고 인원 (예상)" 표현만 쓰고, 문구는 확정 전까지 임시로 둡니다.

사용자 말: "인천공항 API 중에 출국장 면세장 같은 구조물 정보는 없다고 들었다. 사실이 아니라면 찾아서 추가하고 싶다."

| 찾는 정보 | 있는지 | 근거 |

| 출국장 **혼잡·인원** (인천) | **있음** | 승객 예고 D (T1 출국장 1~6, T2 출국장 1~2) |
| 출국장 **구조·위치** (인천) | 명세에 없음 | A·D에 위치 좌표 필드 없음 |
| 면세장 **매장 목록·위치** (인천) | 검색 기준 **찾지 못함** | 인천 출국장 면세점 매출 정보(공공데이터 15156119)는 매출 통계로 매장 위치를 주지 않음 |
| 상업시설 (KAC 공항) | 있음 | E (KAC 공항 업체·층) |

- 인천공항공사 "제2터미널 여객기 운항 현황 상세 조회" (공공데이터 15166252, 2026-09-18 등록): 주기장·게이트·체크인 카운터·수하물 수취대 등 터미널 운영 정보를 포함한다고 소개됨. 명세 확보 후 검토 권장.
- 제주 JDC면세점 매장 정보 (공공데이터 15144890): 제주국제공항 면세점 매장 위치·품목. 제주 공항에서만 사용 가능.

## 6. 공통 데이터 모델 (Flight)

A(인천)와 B(KAC)를 한 목록으로 합칠 때 쓰는 공통 구조입니다. 두 API에 모두 있는 항목만 필수로 둡니다.

| 공통 필드 | 인천 A (IIAC) | KAC B | 비고 |
|---|---|---|---|
| `provider` | `IIAC` | `KAC` | 내부용. 화면에는 숨김 |
| `airport` (기준 공항, IATA) | 고정 `ICN` (인천 전용 API) | 요청의 `airport_code` | 요청 기준 |
| `flight_id` | `flightId` | `flightid` | |
| `fid` | `fid` | `fid` | 상세 조회 키 |
| `airline` | `airline` | `airline` | |
| `counterpart_code` (상대 공항, IATA) | `airportCode` | `arrvAirportCode` ※ | 명세 철자 주의 |
| `counterpart_name` | `airport` | `arrAirport` | |
| `scheduled_at` (KST) | `scheduleDateTime` | `scheduledatetime` | YYYYMMDDHHMM |
| `estimated_at` | `estimatedDateTime` | `estimateddatetime` | 없으면 `null` |
| `status` | `remark` | `rmkKor` | 원문 보관 |
| `line` (국내/국제) | `typeOfFlight` (I/D) | `line` (국내/국제) | 표기 통일 |
| `terminal` | `terminalId` | (없음) | KAC는 "정보 없음" 표시 |
| `gate` | `gateNumber` | (없음) | KAC는 "정보 없음" 표시 |

명세 이슈 메모
- IIAC 응답 표는 `estimatedDatetime`, 샘플 XML은 `estimatedDateTime`으로 대소문자가 다릅니다 → **대소문자 무시**로 읽습니다 (확인 프로그램에 반영).
- KAC 운항 응답 표에는 도착 공항 코드가 `arrvAirportCode`로 적혀 있습니다 → 실제 응답을 보고 확정합니다. 확인 프로그램은 두 이름 중 하나만 있어도 통과하게 했습니다.

## 7. Tool 정의 (명세 2.3, F3001~F3004)

모든 Tool은 `{"ok": true, "data": ...}` 또는 `{"ok": false, "error": {"code", "message"}}`로 답하고, 예외를 밖으로 던지지 않습니다.

| Tool 이름 | 구분 | 명세 | 입력 | 출력 | 실패 코드 |
|---|---|---|---|---|---|
| `search_departures` | 외부 API (A + B) | F3002 후보 | `airport`(IATA), `date`(YYYY-MM-DD, 기본 오늘 KST), `from_time`·`to_time`(HHMM, 기본 0000·2359), `destination`(IATA, 선택) | `flights[]` (공통 모델), `requested_date`, `queried_date`, `is_estimated` | `UNSUPPORTED_AIRPORT`, `NO_RESULT`, `DATE_OUT_OF_RANGE`(→ 가장 가까운 허용일로 조정하고 `is_estimated=true`), `INVALID_KEY`, `UPSTREAM_ERROR` |
| `get_flight_detail` | 외부 API (A: fid 조회 / B: depart + f_id) | F3003 상세 | `airport`, `fid` | `gate`, `terminal`, `checkin_range`, `status`, `codeshare`, `aircraft_type`. 없는 값은 `null` | `NOT_FOUND`, `NO_SCHEDULE`(예정 시각 없음 → 판단 제외), `INVALID_KEY`, `UPSTREAM_ERROR` |
| `get_airport_congestion` | 외부 API (C) | F3004 보조 | `airport`(IATA, 5개 공항 중 하나) | 구간별 레벨과 레벨 이름(1 원활 ~ 4 매우 혼잡), `prc_time` | `UNSUPPORTED_AIRPORT`(5개 외), `NO_RESULT`, `UPSTREAM_ERROR` |
| `get_incheon_passenger_forecast` | 외부 API (D) | F3004 보조 | `date_offset`(0=오늘, 1=내일) | 시간대별 T1·T2 출국장 인원 (예상) | `NO_RESULT`, `QUOTA_EXCEEDED`, `UPSTREAM_ERROR` |
| `get_commercial_facilities` | 외부 API (E) | F3004 보조 | `region`(지사명, 선택) | 계약 유효 업체 목록 (업체명, 층, 국내/국제선). 종료일 지난 계약은 제외 | `NO_RESULT`, `UPSTREAM_ERROR` |

Tool 설명문 작성 원칙 (명세 2.3)
- 기능이 아니라 **언제 쓰는지**를 씁니다. 예: "출발 시간표를 물으면 쓴다. 날짜를 주지 않으면 오늘로 본다."

지도 링크 (Tool 아님, 실행 흐름이 직접 처리)
- 키 없이 되는 방식: `https://www.google.com/maps/search/?api=1&query=<공항명 또는 좌표>`
- 선택 사항: `GOOGLE_MAPS_API_KEY`가 있으면 Geocoding으로 좌표를 얻어 지도에 핀을 찍습니다. 키가 없으면 링크 방식으로 동작합니다.

## 8. 메인 Agent 실행 흐름 (명세 2.4, F3005~F3011)

```
분석 → 계획 → 실행 → 판단 → 응답
 │       │       │       │       └─ 추천 항목 + 판단 기준 + Tool 근거 + 제외 사유 + 안내
 │       │       │       └─ 제약 계산 (필요 시각 역산) → 충족 없으면 재계획(최대 3회)
 │       │       └─ Tool 호출, 결과 보관, 실패는 사유를 기록하고 다음 단계로
 │       └─ 필요한 Tool과 순서만 계획 (인사·사용법은 계획 생략)
 └─ 기준 / 선호 / 제약 추출. 없는 값은 채우지 않고 비움
```

제약 계산식 (F3008)
- `기준 시각` = `estimated_at`이 있으면 변경 시각, 없으면 `scheduled_at`
- `공항 도착 기한` = `기준 시각` − `체크인 여유(분)` (사용자 입력)
- 체크인 여유가 입력되지 않으면 계산하지 않고 **되묻습니다.** 기본값을 임의로 두지 않습니다.
- 충족 조건: `사용자의 공항 도착 예정 시각 ≤ 공항 도착 기한` (예: 집에서 출발해 공항에 8시 30분에 도착할 예정이면, 기한이 8시 30분 이후인 편만 충족)
- 혼잡도·승객 예고는 **판정에 넣지 않고** 참고 정보로만 보여 줍니다.

Memory (F3010)
- 보관: 마지막 출발 공항, 목적지, 날짜, 시간창, 체크인 여유, 직전 후보 요약
- 보관하지 않음: Tool의 원본 응답 (요약만 보관, 명세 2.4 예시)

## 9. 저장 구조 (F3015~F3016, 명세 2.5)

탑승 계획 1건
- `id`, `created_at` (생성 일시)
- `date`, `flight_id`, `airline`, `airport`, `counterpart_code`, `counterpart_name`
- `scheduled_at`, `estimated_at`, `arrive_by` (공항 도착 기한), `checkin_buffer_min`
- `terminal`, `gate` (없으면 `null`)
- `maps_url`, `memo`, `source_summary`

겹침 처리
- 같은 날짜에서 `[arrive_by, scheduled_at]` 구간이 겹치는 계획이 있으면 **저장은 하되** 저장 결과 응답에 겹치는 계획 목록을 함께 씁니다.

실행 로그 (F3012~F3014)
- 이벤트: `session_id`, `type`(step_enter/step_exit/tool_call/tool_result/llm_decision/replan), `ts`, `payload`
- 로깅 Agent는 LLM 없이 받은 순서대로 세션 단위로 저장합니다. 저장이 실패해도 대화는 계속됩니다.

## 11. 명세 발견 사항 (구현 시 주의)

1. KAC 출발 응답에 게이트·터미널이 없어서, KAC 공항은 탑승구를 "제공되지 않음"으로 표시합니다.
2. KAC 상세 목록(`flight-status/detail`)에는 편명·공항 필터가 없습니다. 상세 Tool은 출발 조회 API(`depart`)에 `f_id`를 넣어 처리합니다.
3. KAC 혼잡도는 5개 공항 전용입니다. 나머지 공항은 "데이터 없음".
4. 인천 승객 예고는 출입국 1시간 단위이며 오늘·내일만 있습니다 (`selectdate` 0 또는 1).
5. 상업시설 데이터에는 공항 코드가 없고 지사명(예: 군산지사, 제주지역본부)만 있습니다. 지사 → 공항 매핑표를 직접 만들어야 합니다.
6. 상업시설의 계약 종료일이 지난 항목이 섞여 있습니다. 종료일 기준으로 제외합니다.
7. 대표 요청 조회 기준이 조회 허용 범위(D−3 ~ D+6)를 벗어나면 **가장 가까운 허용일로 조정하고 응답에 밝힙니다** (명세 F3002).
8. 명세 샘플의 `totalCount` 예: KAC 실시간 운항은 약 8,000건. 한 번에 전부 받지 말고 `airport_code`, 시간 구간으로 좁혀 호출합니다.
